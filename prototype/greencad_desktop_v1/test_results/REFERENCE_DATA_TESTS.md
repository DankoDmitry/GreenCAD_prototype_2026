# GreenCAD Desktop 0.4: проверка общего пакета и встроенных справочников

Дата сборки: 29.09.2026. База — main `dfc645c1792ec062f33d46b0431a0ae3f6fcd8ce`.
Среда: Linux x86-64, Python 3.13.5, Tk 8.6.16, ezdxf 1.4.4, Shapely 2.1.2, Xvfb.
Нативная Windows, МосТех.ОС, AutoCAD/nanoCAD не запускались.

## Состав испытаний

Предыдущие 108 тестов сохранены; проверка версии сохраняемого проекта теперь
ожидает 3, отдельно проверена загрузка прежнего формата 2. Добавлены 27 тестов
ядра и 9 тестов настоящего Tk-интерфейса: всего 144 (98 core, 46 GUI).

Проверяются:

- Детерминированная пересборка из двух оригинальных JSON и двух XLSX v1;
  совпадение текущего пакета и повторной сборки. LF/CRLF профиля не меняет пакет.
- Все 2 863 исходные строки значений: сохранены значения, статусы, контексты,
  источники и исходные формулировки. Идентификаторы не объединялись.
- 7 567 сопоставлений ожидаемых результатов из исходного реестра: 329×8
  территориальных отметок и 329×5×3 почвенных условий. Эти сопоставления входят
  внутрь одного теста; они НЕ прибавляются к числу тестов набора.
- Требование дренированности тсуги V02205 действительно связывается с E2210.
  Изменение тестовой копии этой ячейки и сборка меняют ответ правила без правки
  формулы. Примечания/флаги сами по себе больше не определяют значение требования.
- План и карта обращаются к одному набору типизированных значений.
- Отсутствующие размеры/показатели остаются UNKNOWN; радиус символа не используется.
- Ошибочные типы, неизвестные ссылки, дубли ID/фактов, изменённая неподдерживаемая
  формула, формула с устаревшим XLSX-кэшем отклоняются.
- Старые live-JSON выборки не перечитываются окном/исполнителем вместо снимка.
- Просмотр и сортировка не меняют проект. Данные публичного API — копии; изменение
  возвращённой записи не меняет основной пакет.
- Обновление явно подтверждается, сохранённые настройки не заменяются базовыми;
  расчёты устаревают, Undo возвращает прежний снимок.
- Проект v3 сохраняет снимок и загружается даже при недоступном текущем пакете
  установки. Повреждённый хеш/состав ZIP отклоняется. Старые .gcp читаются с уведомлением.
- Реальные Tk-кнопки, поиск, карточка происхождения, эффективный TEST-порог,
  неподключённые правила, обновление/отмена, сохранение и повторное открытие.
- Кнопки нижней панели доступны при минимальном размере и повышенном Tk scaling;
  это не имитация нативного Windows DPI.

Скриншоты сняты с работающего Tk-окна через Xvfb. Это не макеты.

## Команды

```bash
python tools/build_reference.py --check
xvfb-run -a python -m unittest discover -s tests -v
python tools/check_plan.py examples/demo_session.gcp --output /tmp/checks.json
python tools/map_admissibility.py examples/demo_block.dxf --type T1 --step 2 --output /tmp/map.json
```

Полные протоколы запуска сохраняются отдельно с дистрибутивом. Перед публикацией
архив обновления накладывается на распакованную 0.3 и проверяется повторно.

## Что это НЕ доказывает

Это проверка реализации и согласованности с собранными реестрами, не повторная
юридическая/ботаническая экспертиза исходников. Новые нормы, критерии и автоматическая
расстановка не реализованы. TEST-отступы остаются ненормативными. Адаптер XLSX
ограничен перечисленными в docs/REFERENCE_DATA.md листами/столбцами схемы v1.
Ни работа на предельных CAD-файлах, ни скорость на пользовательском ПК этим набором
не сертифицированы. Ссылки на документы/их статусы сохранены из источников.
