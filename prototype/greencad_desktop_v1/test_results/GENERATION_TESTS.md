# GreenCAD Desktop 0.6 — проверка генератора

Дата: 29 сентября 2026 года. Основа — опубликованная версия 0.5,
коммит `0eaefb18ff0787aacd48d2441b043a38d906422d`.

## Среда и результат

Linux x86-64; Python 3.13.5; Tcl/Tk 8.6.16; Xvfb; ezdxf 1.4.4;
Shapely 2.1.2. Нативная Windows, МосТех.ОС, AutoCAD/nanoCAD не запускались.
Новых зависимостей нет. Проверка GitHub Actions для этой поставки ещё не выполнялась.

Полный локальный запуск `xvfb-run -a python -m unittest discover -s tests -v`:
**263 теста, OK**. Из них 208 прежних, 40 новых core, 15 новых Tk;
итого 184 без обязательного окна и 79 GUI. Финальный локальный запуск — 132.055 с.
Протокол — `test_results/GENERATION_TESTS.txt`.

`python tools/build_reference.py --check` прошёл. Канонический ID справочника:
`046a5e8414f1686fe83c502e87e1ea9908b8a8cf8405d1e7987d0b743d2a6f13`.
Фактические байты исходных книг/JSON, reference_bundle и requirements совпадают с 0.5.
Сборка нового алгоритма не меняла нормативные данные и не добавляла видовых размеров.

## Что проверяется новыми тестами

- Детерминированные координаты, ID, очередность; корректные квоты нескольких типов.
- Все исходные ручные посадки неизменны; учитываются закреплённые, скрытые, вне выбранной зоны.
- Независимые аналитические сравнения расстояний между центрами, резервов и прямой газа.
- Позднее добавление типа с большим расстоянием обновляет кэш/индекс, не ослабляет условия.
- Подготовка эффективных правил не меняет сеанс до применения; применение и Undo — одно действие.
- Устаревший, изменённый, пустой, повторно применяемый или не прошедший финальную проверку вариант отклоняется.
- Полный валидатор действительно пересоздаёт пространственный индекс: тест намеренно ломает
  промежуточное обновление индекса, получает VALIDATION_BLOCKED и запрещённое применение.
- Неизвестные обязательные параметры/операторы не становятся разрешением; рекомендации отделены.
- Строго выбранная зона, а не объединение соседних; отверстия/несколько компонентов; миллиметры и сдвиг.
- Радиус знака не влияет на генерацию; zero-reserve/zero-spacing запрещён; лимиты ресурсов проверяются заранее.
- Отмена до начала, в цикле и на финальной проверке не меняет проект и не публикует частичный результат.
- Причины всех рассмотренных отказов; неполное заполнение не выдаётся за доказанную невозможность.
- Перенос сохранения .gcp, обратный экспорт DXF с профилями и метаданными происхождения генерации.
- CLI READY, EMPTY, файлы отчётов и защита существующих выходов.
- Реальные кнопки, флажки, порядок типов, ghost-preview, Apply/Undo/Redo, повторное открытие проекта.
- Сохранение JSON, устаревание, отмена, совместимость с картой, нижние кнопки при малом окне и Tk scaling.
- Искусственно выброшенная ошибка worker возвращает управление и не добавляет посадок. В логе
  этой успешной проверки намеренно виден traceback `EditorErrorForTest: test-error`.

Тесты на разных масштабах Tk не являются нативной проверкой Windows DPI.
Полная база 208 прежних тестов также включает проверки сборщика/источников, шаблонов,
редактора, DXF, файлов проекта и карт. Подробности прошлых этапов — в их отдельных отчётах.

## Демонстрационный сквозной запуск

`python tools/make_generation_example.py`: из `examples/demo_templates.gcp` сохранены 6
ручных экземпляров и найдены 80 новых: T1/T2/T3/T4 по 20. READY, обязательные проверки PASS.
Сохранены настоящий результат DXF, переносимый проект, полный журнал генерации и проверки.
Числа условий синтетические TEST. Это не ручная расстановка, выданная за результат генератора.

В отдельном запуске через настоящее окно: тот же результат; core около 1.98 с,
завершение с опросом интерфейса/ожиданием кадра около 2.97 с. Пик RSS процесса около 200 МиБ.
Это один замер небольшого примера при параллельной нагрузке тестирования, не гарантия
быстродействия на реальных тяжёлых DXF. Предельные 50 000 пробных клеток / 2 000 новых
посадок не использовались как нагрузочный benchmark.

Снимки окна, формы генерации и отчёта сняты с реального Tk-приложения под Xvfb.
Распознавание инженерных планов или графических условных знаков не использовалось.

## Упаковка

Обновление содержит только изменённые/новые файлы поверх 0.5; без .git, .venv и пользовательских
проектов. В полной сборке — корневая папка greencad_desktop_v1. Повторная проверка выдаваемых
сборок фиксируется отдельным файлом `test_results/GENERATION_PACKAGE_TESTS.md`.

Эти тесты проверяют алгоритм и программу в объявленной модели. Они не подтверждают
корректность всех исходных нормативных трактовок, полноту DXF или оптимальность композиции.


Полная сборка и наложение обновления поверх 0.5 повторно прошли по 263 теста.
См. `GENERATION_PACKAGE_TESTS.md` и два отдельных лога. Исполняемые файлы после
этих прогонов не менялись.
