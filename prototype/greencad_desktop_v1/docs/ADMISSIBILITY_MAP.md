# GreenCAD Desktop 0.3 — карта допустимости

## Что добавлено

Кнопка **«Карта допустимости…»** строит слой для фиксированных проектного типа,
растения (необязательно, если выбранные проверки его не требуют), режима
корнезащиты и параметров участка. Можно показывать итог обязательных условий
или одну компоненту — результат отдельного выбранного правила.

Это не авторасстановка. Гипотетические точки карты не попадают в список посадок.
Существующие посадки не добавляются в карту как препятствия; проверки вида
«расстояние между новыми посадками» явно исключаются и перечисляются в отчёте.
Для полного плана по-прежнему нужна кнопка **«Проверить допуски»**.

## Обновление и использование

При обновлении через GitHub сначала объедините PR в main, затем закройте редактор,
в GitHub Desktop выполните Fetch origin / Pull origin. Запуск — START_WINDOWS.bat.
Новых библиотек относительно 0.2 нет. При обновлении архивом резервируйте локальные
правки; не смешивайте обновление архивом с получением того же изменения через Git.

1. Откройте demo_block.dxf или свой подготовленный DXF.
2. В «Выбрать проверки…» включите условия и нажмите «Готово».
3. Нажмите «Карта допустимости…»: выберите тип, при необходимости растение,
   флаг корнезащиты и шаг в метрах. Начальный шаг — 1 м.
4. Нажмите «Построить карту». Во время работы доступны прогресс и «Стоп».
5. В списке над картой переключайте итог и отдельные правила. Повторный расчёт
   для переключения уже рассчитанных компонентов не нужен.
6. В режиме «Проверить место» щёлкните в произвольной точке. Справа появится
   объяснение именно для координаты щелчка, а не ближайшей клетки. Нарушения
   показываются первыми; отключённая форма редактирования уступает место тексту.
7. Для возврата к редактированию выберите «Выбор / перенос» или «+ Посадка».
   Флажок «Показать» скрывает слой без удаления результата.

Для начального TEST-порога у газопровода demo y=30:
(40,31) нарушает условие 3 м; (40,33) выполняет его ровно на границе.
Это условные технические проверки, не цитаты нормативного документа.

## Статусы

* Зелёный — выполнены обязательные проверки участка (либо показанное отдельное правило).
* Красный — найдено нарушение.
* Жёлтый — недостаточно данных.
* Серый — обязательные условия не проверены либо правило не применимо.
* Фиолетовый — ошибка обработчика.
* Оранжевый — рекомендация в отдельном слое, не обязательный запрет.

Итоговый слой объединяет только обязательные SITE_POINT-проверки. Рекомендации
имеют самостоятельные компоненты: отсутствие данных для рекомендации не создаёт
запрета и не определяет итог обязательных условий. При выборе только рекомендаций,
только проверок плана или пустого списка итог NOT_CHECKED, а не PASS.
Неизвестные ID, отсутствующие обработчики и неподтверждённый scope дают UNKNOWN.
При FAIL и UNKNOWN одновременно итог FAIL, но объяснение сохраняет оба результата.

Зелёный в отдельном слое означает только выполнение этого правила. Даже итоговая
зелёная область не означает возможность одновременно посадить растения во всех
её точках и не является комплексным нормативным заключением.

## Геометрия и сетка

Область карты — объединение явно переданных корректных зелёных зон из исходного
DXF. Используется расчётный адаптер check_geometry.py, не экранная геометрия.
Отверстия и раздельные участки сохраняются при проверке принадлежности центров.
При невозможности достоверно построить область карты расчёт отклоняется с причиной;
прямоугольник по экранным границам не подставляется вместо области.

Результат хранится на сетке в метрах. Проверяются центры клеток; последняя клетка
может быть короче шага и её центр рассчитывается по фактическим границам.
За пределами зоны центры имеют OUTSIDE и не окрашиваются. Цветной прямоугольник
лишь показывает результат в центре: возле края и отверстий он может выступать
за точную границу на часть шага. Никакого утверждения о допустимости всей клетки
нет. В узкой зоне центры могут вообще не попасть внутрь: это повод уменьшить шаг,
не доказательство невозможности посадок.

Лимиты: 50 000 клеток ограничивающего прямоугольника, 2 000 000 пар клетка–правило.
Слишком мелкая сетка отклоняется до выделения массивов, с предложением укрупнить шаг.
Отмена не публикует частично рассчитанную карту. Цвета хранятся только в UI.
Результаты объединяются по горизонтальным сериям и вне окна не рисуются;
не создаётся отдельный интерактивный Canvas-объект для каждой точки проверки.

Проверка по щелчку снова вызывает исполнители по исходным координатам. «Фактическая»
здесь означает не привязанная к узлу сетки; геометрия GEOS использует double и
не является интервально сертифицированным расчётом. Нормативные расстояния,
размеры корней и кроны этой доработкой не уточнялись.

## Актуальность, сохранение и DXF

Карта — производный снимок. Изменение условий, параметров среды, типов, классификации,
исходного файла либо справочника делает её устаревшей: цветной слой скрывается,
инспектор и экспорт старого снимка блокируются. Возврат к ровно тем же входам
через Undo позволяет снова использовать снимок.

Перенос и добавление новых посадок, масштабирование, видимость слоёв и выбор другого
типа в левой панели НЕ меняют уже построенную статическую карту: её тип и растение
написаны над картой и остаются фиксированными. Для другого типа нажмите «Карта
допустимости…» и выберите другой шаблон. Полная проверка плана остаётся отдельной.

«JSON карты…» сохраняет параметры, решётку, коды статусов, данные каждого слоя,
источники правил, хеши исходника/справочников и перечень исключённых проверок плана.
Это экспорт исследовательского результата, не сохранение сессии и не новый DXF.
После открытия .gcp карту необходимо построить заново. Настройки проверок
сохраняются как раньше; шаг и шаблон карты пока живут в открытом сеансе, а
выгруженный JSON содержит их для воспроизведения. Автозагрузка этого JSON в GUI
не реализована.

DXF-экспорт и .gcp остаются совместимы с 0.2 (схема проекта 2). Растения экспортируются
прежним механизмом. Сама растровая подсказка карты в DXF не записывается.
Её получение не изменяет исходный файл, историю действий и отчёт проверки плана.

## Архитектура и подключение критериев

`checks.PointEvaluator` — общий диспетчер операций для validate_plan и карты.
Геометрия/справочники подготавливаются один раз на проход, а не на каждую клетку.
`aggregate(..., mandatory_only=True)` выбирает пересечение обязательных результатов;
обычный отчёт плана сохраняет прежний вариант агрегации.

`data/check_rules.json`: добавлено evaluation_scope. Для независимой от новых
посадок проверки явно укажите SITE_POINT; для зависимости от плана — PLAN.
Новый неизвестный scope нельзя автоматически принять за независимую проверку.
Критерий с новой формулой требует оператора в checks.OPERATORS, а не только строки
таблицы. Диспетчер карты и Canvas при этом не меняются.

`admissibility.py`: MapOptions, GridSpec, MapKernel, AdmissibilityMap, build_map.
`admissibility_ui.py`: настройки, отмена/прогресс, переключение слоёв, объяснение точки.
`view.py`: только точки подключения к отрисовке слоя и щелчку; правил в Canvas нет.
Tk-вызовы выполняются в главном потоке. Геометрия и вычисление карты — через
существующий последовательный фоновый исполнитель. Во время расчёта редактирование
заблокировано; контролы отмены и события окна обслуживаются.

## Без окна

```powershell
.\.venv\Scripts\python.exe tools\map_admissibility.py examples\demo_block.dxf --type T1 --step 1 --output admissibility_map.json
```

Дополнительно: --plant ID, --root-protection, --settings settings.json,
--metres-per-unit для unitless DXF. .gcp содержит собственные настройки.
Код 0 означает успешное создание карты, которая может содержать красные/неизвестные
клетки. Код 2 — ошибка подготовки или записи. Невозможность получить допустимую
композицию этот инструмент не доказывает.
