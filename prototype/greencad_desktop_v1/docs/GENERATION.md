# GreenCAD Desktop 0.6 — расстановка расчётных типов

## Что делает эта версия

Одна выбранная зелёная зона → заданная очередь расчётных типов и лимиты → конечный
воспроизводимый проход → независимый повторный проход проверок → предварительный
вариант → явное применение. Генерация работает и для анонимных шаблонов.
Если виду уже назначено наполнение, его известные требования тоже участвуют.
Автоматического выбора ботанического вида нет.

Исходная подоснова, справочники, ручные посадки и их свойства не изменяются.
Результат не является доказанно оптимальной композицией или нормативной экспертизой.
Численные отступы и габариты демонстрационного проекта по-прежнему TEST.

## Быстрый запуск

1. Получите обновление поверх 0.5 и запустите `START_GENERATION_WINDOWS.bat`.
   Либо откройте `examples/demo_templates.gcp` обычной кнопкой «Открыть».
2. Нажмите **«Расставить типы…»**. Выберите зону `green_01` и шаг поиска 1 м.
3. Отметьте T1–T4. Лимит каждого — максимум НОВЫХ экземпляров, начальное значение 20.
   Чтобы изменить лимит, выделите строку, введите число, нажмите «Записать лимит».
   Последний редактируемый лимит также записывается при нажатии «Построить вариант».
4. Кнопки **«Раньше» / «Позже»** меняют порядок. Он не выводится из размера картинки.
   Для схемы «от больших к малым» поставьте типы в соответствующем порядке сами.
5. Нажмите **«Построить вариант»**. Пока идёт расчёт, доступны прогресс и «Стоп».
6. На карте появятся пунктирные резервные круги. Это ещё не посадки проекта.
   Шесть ручных посадок остаются на прежних местах. По умолчанию в этом примере
   добавляется 20 экземпляров каждого типа: 80 новых, 86 всего.
7. **«Результат…»** показывает количество, обязательные проверки и причины пропусков.
   **«Применить вариант»** добавляет группу одним действием. **Ctrl+Z** отменяет всю группу.
   **«Убрать вариант»** только убирает предварительный слой/отчёт; принятые посадки не удаляет.
8. После применения доступны обычные перенос, подбор растения, сохранение .gcp и экспорт DXF.
   Для независимой повторной проверки используйте «Проверить допуски».

`START_WINDOWS.bat` по-прежнему открывает базовое демо. Его графические типы могут не
иметь расчётных профилей; сначала включите профиль в карточке типа. Для первого
испытания удобнее именно `START_GENERATION_WINDOWS.bat`.

## Общий механизм правил

Генератор использует `checks.PointEvaluator` и текущий `ReferenceBundle`, а не цвет
клетки карты. Геометрия считывается из исходного DXF в метрах прежним расчётным
адаптером. Дополнительное ограничение выбранной зоной — вызов того же оператора
`inside` с явным ID области. Замкнутые контуры, отверстия, раздельные компоненты
проверяются геометрически. Сетка отображения и сетка генерации независимы.

Рабочее задание всегда включает минимум:
- `R.domain` — размещение в зелёных зонах;
- `project.excluded` — исключённые площади;
- `R.spacing` — расстояние между посадками.

Когда эти флажки выключены, они включаются только в частной копии задания. Окно и
отчёт явно об этом сообщают. В проекте настройки меняются одновременно с применением
варианта и отменяются тем же Ctrl+Z. Остальные выбранные правила сохраняются.
Назначение этих трёх защит — не молча заполнять участок пересекающимися знаками.

Проверяется резерв профиля, не радиус условного знака. Попарное условие используется
из прежнего исполнителя: максимум общего минимума, обоих типовых минимумов и суммы
расчётных резервов. Корнезащита не уменьшает отступы. Новым экземплярам REQUIRED
задаётся флаг true; FORBIDDEN и ANY начинают с false.

Генератор не отключает конкретное растение, уже назначенное типу, и не подставляет
требования профиля вместо неизвестных характеристик вида. Поэтому назначенный вид
при неполном паспорте может дать UNKNOWN и не получить новых экземпляров.

## Алгоритм без претензии на оптимальность

1. Зафиксировать состояние, справочник, выбранные типы, область и параметры.
2. Проверить ВСЕ уже расставленные посадки с эффективным набором правил.
   Нарушение, ошибка либо нехватка обязательных данных блокирует генерацию;
   приложение ничего не исправляет само. Посадки в других зонах тоже сохраняются
   и участвуют в общей проверке и попарных условиях.
3. Разбить ограничивающий прямоугольник выбранной зоны на клетки заданного шага.
   Последняя клетка может быть меньше шага; проверяется её фактический центр.
   Оставить центры, действительно принадлежащие выбранной области.
4. Идти по типам в заданной очереди. Для каждого просматривать центры по возрастанию Y,
   затем X. Выполнять все активные применимые условия и ограничение выбранной зоной.
5. Добавлять только вариант с подтверждёнными обязательными условиями. После принятия
   обновлять частный список и пространственный индекс; следующая точка видит все ранее
   принятые посадки. Рекомендации сохраняются, но не компенсируют обязательные запреты
   и не становятся ими. Переходить к следующему типу по достижении квоты или исчерпанию
   кандидатов. Не просмотренные после квоты позиции не считаются отказами.
6. Заново построить контекст/индекс и проверить весь итоговый план. Дополнительно
   проверить все новые экземпляры относительно выбранной зоны. Этот проход не доверяет
   кэшу или предварительным статусам генерации. Это повторная проверка, не независимое
   второе нормативное ядро: формулы общие.
7. Показать законченный вариант; применить только после подтверждения пользователя.

Порядок и шаг определяют композицию. Алгоритм не пытается равномерно покрыть всю
территорию, найти максимум растений, перераспределить квоты или улучшить художественную
композицию. Начало заполнения с одной стороны — ожидаемое свойство этого baseline.
При одинаковом полном входном снимке и параметрах получаются одинаковые ID и координаты.
Временные отметки отчётов и служебная сериализация DXF могут различаться.

## Состояния и полнота

- READY: все заданные верхние лимиты достигнуты, окончательные обязательные проверки выполнены.
- PARTIAL: найдено меньше лимита; найденную проверенную часть можно принять.
- EMPTY: новых точек в данном проходе нет; это НЕ доказательство невозможности иных размещений.
- BASELINE_BLOCKED: ручной/исходный план не подтверждён по обязательным условиям.
- VALIDATION_BLOCKED: окончательная проверка не подтверждает вариант; применение запрещено.

Итог обязательных проверок отделён от общего отчёта: неизвестная рекомендация может
остаться UNKNOWN, не запрещая размещение при выполнении обязательных условий.
Ошибка обработчика прерывает расчёт, а не маскируется под геометрическую невозможность.
Неизвестные правила/scope блокируют подготовку; отсутствующий SITE-обработчик даёт UNKNOWN.
Новые глобальные PLAN-операторы, кроме попарного spacing, требуют явного адаптера генератора;
они не игнорируются. Нулевой одновременно резерв и минимум расстояния не допускаются.

## Ограничения ресурсов и отмена

До 20 типов в задании, до 2 000 новых и до 20 000 суммарных посадок; до 50 000 клеток
ограничивающего прямоугольника, 200 000 пар «кандидат–тип», 1 000 000 планируемых
вызовов проверок за проход отбора. Слишком мелкий шаг отклоняется до выделения
больших массивов. Все рассмотренные отказы с числовыми значениями и объектами
сохраняются; окно показывает первые 100, полный список — JSON.

Расчёт идёт в существующем последовательном фоновом исполнителе, без Tk-вызовов
из потока. Рабочий проект не редактируется во время вычисления. «Стоп» проверяется
между операциями/точками и в финальном проходе; отдельную библиотечную геометрическую
операцию нельзя прервать посередине. Частичный результат отменённого задания не
показывается и не применяется. Старый предварительный результат новый запуск заменяет.

## Применение, актуальность и сохранение

Вариант связан с контрольной суммой исходного состояния. Ручная правка, замена типа,
правил, среды, справочника или исходной классификации обесценивает вариант и скрывает
пунктир. Изменение масштаба и видимости исходных слоёв не меняет условия. Все ручные
посадки, включая закреплённые и скрытые, учитываются. При применении проверяется
соответствие снимка и целостность результата; повторное применение не дублирует посадки.

Предварительный вариант не изменяет .gcp или DXF и не сохраняется автоматически при
закрытии программы. Кнопка «JSON результата…» выгружает полный отчёт с состоянием.
Принятые посадки и эффективные параметры сохраняются обычным Ctrl+S. Формат .gcp остаётся
v4, метаданные DXF — v2, новых зависимостей нет. В `Placement.properties.generation`
сохраняются job_id, зона, шаг, порядок/лимиты и индекс позиции. История Undo живёт в сеансе.
Полный отчёт поиска не встраивается в .gcp: сохраните JSON отдельно. После повторного
открытия .gcp выполняйте обычную проверку заново.

Экспорт исходника и результатов работает прежним механизмом с проверкой сохранности.
Объяснения принятых посадок попадают в обычный `.checks.json`; полный протокол генерации
выгружается отдельно. Выгрузка черновика по-прежнему не превращает его в допустимый план.

## Без окна

```powershell
.\.venv\Scripts\python.exe tools\generate_layout.py examples\demo_templates.gcp --zone green_01 --type T1:20 --type T2:20 --type T3:20 --type T4:20 --step 1 --output result.dxf --project-output result.gcp
```

Лимиты в --type относятся к новым экземплярам; порядок аргументов задаёт очередь.
Дополнительно доступны --settings и --metres-per-unit для unitless DXF.
Входной DXF должен нести расчётные типы в метаданных либо используйте подготовленный .gcp.
По умолчанию существующие выходы не заменяются; --overwrite разрешает замену выходов,
но не входных путей. При отказе/EMPTY записывается .generation.json, но не новый DXF.
Все выходы имеют независимые операции записи; это не атомарная многокомпонентная транзакция.
Коды выхода: 0 — READY; 2 — PARTIAL с пригодным результатом; 3 — пусто/заблокировано;
4 — ошибка чтения, подготовки или записи.

`python tools/make_generation_example.py` создаёт `examples/demo_generated.*`
настоящим генератором из исходного `demo_templates.gcp`. Это 6 сохранённых ручных и
80 автоматически найденных экземпляров, а не вручную нарисованная демонстрация.

## Модули и проверка

`generation.py` — данные задания, отбор, свежая проверка, атомарное применение в историю.
`generation_ui.py` — форма, прогресс, пунктирный слой и отчёт.
`checks.PointEvaluator.append_placement` — обновление контекста на частном снимке.
`tools/generate_layout.py` — тот же путь без окна.

Тесты: `RUN_TESTS_WINDOWS.bat` либо `xvfb-run -a python -m unittest discover -s tests -v`.
См. `test_results/GENERATION_TESTS.md` для фактически проверенных версий и границ.
