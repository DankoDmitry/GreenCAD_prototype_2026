# Обновление GreenCAD Desktop 0.3 → 0.4

## Что изменилось

Вычислитель и новое окно **«Справочники…»** получают данные из одного проверенного
пакета, закреплённого за открытым проектом. В пакете сохранены исходные реестры,
значения, примечания, связи, источники и адреса ячеек. Требования к грунту читаются
из типизированных записей, а не восстанавливаются только по номеру примечания.
Сборщик позволяет воспроизвести пакет из комплектных исходников или заданных книг v1.

Численные отступы остаются TEST. Эта версия не добавляет новые нормы,
ботанические размеры или генератор посадок. Неизвестные значения не заменяются нулём.

## Установка поверх существующей папки

1. Сохраните текущий проект, закройте редактор. Сохраните отдельную копию прежних
   `.gcp`: после записи новой версией они переходят на формат 3.
2. Собственные изменения кода зафиксируйте в GitHub Desktop или скопируйте папку.
   Архив предназначен для версии 0.3 после объединения карты допустимости и
   исправления кнопки «Готово» (проверенная база: `dfc645c`).
3. Скопируйте содержимое `GreenCAD_Desktop_v0.4_update.zip` непосредственно в
   `D:\ЗагрузкиD\greencad_desktop_v1`, рядом с `run_editor.py`, подтвердив замену.
   Вложенную папку создавать не нужно. `.git`, `.venv` и ваши сессии архив не содержит.
4. Запустите `START_WINDOWS.bat`. Новых зависимостей нет, установка не требуется.
5. Откройте демо либо свой `.gcp`, нажмите «Справочники…» рядом с кнопками проверок.
6. После проверки можно зафиксировать обновление коммитом и нажать Push origin.
   Сам архив не выполняет операций с GitHub.

Полная сборка `GreenCAD_Desktop_v0.4.zip` предназначена для отдельной установки.
При её использовании настройте окружение через `setup_windows.bat`, как раньше.
Не смешивайте установку поверх папки и другую одновременно работающую копию.

## Первый опыт

В «Растения» найдите Тсугу канадскую, строку `PER.perspective.conifer_tree.004`.
Внизу выберите «Требует дренированной почвы»: справа видны значение `Да`, запись
`V02205`, лист `03_Значения`, ячейка `E2210` исходной книги и проверка `R.soil.drained`.
В основной таблице диаметр кроны остаётся «Нет данных», если его нет в реестре.

На вкладке «Правила размещения» найдите `project.gas`: эффективный минимум будет
взят из текущих настроек проекта, а не из размера нарисованного дерева. Он подписан
как TEST. На вкладке «Условия участка» видны ваши фактические настройки A1 и грунта.

Проверка дренированности и карта используют то же значение, которое показано в
справочнике. Настройки грунта меняются через прежнее окно «Выбрать проверки…».
Справочник открыт только для просмотра: действия поиска/выбора не меняют проект.

## Сохранение и обновление данных

Ctrl+S записывает `.gcp v3` со снимком справочника. Даже после замены пакета поставки
этот файл продолжит использовать свои сохранённые данные. Карта и отчёт после
открытия вычисляются снова. Старые `.gcp v1/v2` открываются с текущим пакетом;
это явно отмечается, поскольку в прежних файлах снимок не сохранялся.

«Обновить пакет…» принимает подготовленный JSON/JSON.GZ. «Собрать из Excel…»
запрашивает две книги v1, проверяет и связывает их поддерживаемые таблицы. Применение
нового пакета требует подтверждения и отменяется через Ctrl+Z. Старые расчёты
становятся неактуальными, пользовательские параметры проекта не перезаписываются.

Адаптер XLSX ограничен определёнными листами и схемой заголовков v1; не все
служебные таблицы являются редактируемым программным входом. Например, изменение
07_Отступы не включает нормативный профиль и не меняет TEST-пороги. Перечень
поддерживаемых листов и CLI-сборка: `docs/REFERENCE_DATA.md`.

Новая колонка не создаёт новую формулу автоматически. Новые типы операций требуют
явного адаптера и тестов. Снимок не встраивается в DXF: для повторяемого рабочего
сеанса используйте `.gcp`; экспорт DXF и его проверка сохранности работают как раньше.

## Проверки

`RUN_TESTS_WINDOWS.bat` запускает набор тестов. Проверка воспроизводимости пакета:

```powershell
.\.venv\Scripts\python.exe tools\build_reference.py --check
```

Нативная Windows и внешние CAD в среде разработки этой сборки не запускались.
Протокол: `test_results/REFERENCE_DATA_TESTS.md`.
