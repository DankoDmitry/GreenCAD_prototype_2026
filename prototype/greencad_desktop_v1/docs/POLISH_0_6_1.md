# GreenCAD Desktop 0.6.1 — свободная расстановка и упрощение окна

Патч поверх версии 0.6 (база GitHub: `32dbce22e39382ee42a8a03d15a7c45d7591817b`).
Исходные справочники, правила и их пороги, DXF-экспорт, схема `.gcp` v4 не изменены.

## Что изменено

1. В «Расставить типы…» добавлены **«Свободная (без рядов)»** и прежний режим
   **«Рядами (как раньше)»**. Для нового задания в окне выбран свободный режим.
2. Поле **«Вариант»** задаёт целочисленный seed, 0–4294967295. **«Другой вариант»**
   увеличивает этот номер на один (максимум переходит в 0). Затем нажмите
   **«Построить вариант»**. Повторные расчёты при тех же входах/режиме/номере/версии
   алгоритма воспроизводят координаты и ID. Время запуска в отчёте, конечно, другое.
3. Жёлтая полоса под верхними кнопками удалена. Сведения о TEST-порогах и о выбранных,
   а не всех возможных, проверках остаются в настройках, справочниках, отчётах,
   экспорте и документации. Убрана полоса, не условия и не их происхождение.
4. В задании уточнены лимиты: до **20 разных проектных типов**, до **2000 новых
   экземпляров суммарно за запуск**. Число 20 в начальных квотах — пример, не предел
   числа деревьев. Лимит 100 допустим. Предельное число объектов проекта не менялось.
5. Нижние кнопки задания закреплены отдельно от прокручиваемой формы.

## Как устроен свободный режим

Работает тот же конечный жадный отбор по типам. Вместо центра каждой поисковой
клетки в ней выбирается одна случайная пробная точка, затем весь набор проб
перемешивается. Точки вне выбранной области (включая отверстия) отсеиваются.
Для каждой оставшейся точки вызываются прежние правила **до её принятия**.
Уже принятые позиции не сдвигаются «для красоты» после проверки.

Это стратифицированные случайные пробы с последовательным отбором по ограничениям,
не оптимизация ландшафтной композиции и не доказательство максимальной плотности.
Нет движения «от одного угла» и точного выравнивания рядов. Случайность не гарантирует
равномерную композицию или заданное количество. На плотной упаковке свободный режим
может разместить меньше деревьев, чем регулярная сетка. Это не повод ослаблять отступы.
Можно изменить номер варианта, уменьшить шаг в пределах лимитов либо выбрать ряды.

Размер клетки — подробность поиска, а не расстояние между деревьями. Число проб и
число проверок ограничены прежними пределами; они не увеличены ради нового режима.
Локальный `random.Random(seed)` не использует и не меняет глобальное состояние RNG.
В каждой клетке в порядке Y/X вызывается `random()` для X, Y и приоритета просмотра.
Приоритеты сортируются с номером клетки как разрешением равенств. Отброс клетки
вне области не сдвигает последовательность генератора для других клеток той же сетки.
Алгоритм и номер записываются в JSON результата и в метаданные принятых посадок.
`grid_index` в свободном режиме — индекс исходной поисковой клетки, НЕ утверждение,
что положение является её центром.

Ручные посадки не изменяются; очередность типов и квоты сохраняются. Новые позиции
учитывают ручной план и ранее принятые позиции того же прохода. Перед применением
по-прежнему выполняется новая полная проверка плана и выбранной зоны.
Операции предварительного просмотра, применения, отмены и Ctrl+Z не изменены.

## Как обновить и попробовать

Сохраните `.gcp`, закройте редактор и зафиксируйте локальные правки либо сделайте копию
папки. Содержимое update ZIP скопируйте **в корень существующей папки 0.6**, с заменой
перечисленных файлов. В архиве нет `.git`, `.venv` или пользовательских сессий.
Новых библиотек нет. При собственных правках тех же файлов сначала сравните их.

Запустите `START_GENERATION_WINDOWS.bat` или откройте свой сохранённый проект.
«Расставить типы…» → «Свободная (без рядов)» → Вариант 1 → «Построить вариант».
Для другой композиции снова откройте задание, нажмите «Другой вариант» и постройте.
Пока вариант не принят, предыдущий заменяется только предварительным слоем.
После **«Применить»** это уже посадки проекта: повторная генерация добавляет к ним,
а не удаляет их. Для замены принятой группы сначала воспользуйтесь Ctrl+Z.

В «Результат…» показаны режим и seed. В принятом `.gcp` координаты и метаданные
сохраняются. Само окно задания сохраняет настройки в текущем сеансе, как и раньше.
После открытия проекта параметры нового задания не восстанавливаются автоматически
по метаданным старой группы; для воспроизведения используйте JSON и исходный план.

Для более чистого вида можно снять «Метки посадок» внизу карты — это уже существующее
действие; координаты и экспорт от него не меняются.

## Без окна / совместимость

Прежние JSON-задания без `layout` и `seed` читаются как `grid`, seed=1. У API и CLI
по умолчанию остаётся `grid`, чтобы прежние скрипты не поменяли способ поиска молча.
В режиме grid номер не влияет на координаты. ID новых запусков после обновления
версии генератора могут отличаться от ID 0.6; существующие посадки не переименовываются.

```powershell
.\.venv\Scripts\python.exe tools\generate_layout.py examples\demo_templates.gcp --zone green_01 --type T1:35 --type T2:20 --type T3:15 --type T4:15 --step 1 --layout natural --seed 7 --output natural_result.dxf --project-output natural_result.gcp
```

Версия генератора 1.1; схема `.gcp` прежняя (4). К исходному DXF при экспорте
добавляются результаты, исходные объекты не меняются. Тестовые числа не становятся
нормативами, новые ботанические сведения не добавлены.

Технический источник: стандартная библиотека Python `random` (локальные генераторы,
повторяемость при seed): https://docs.python.org/3.13/library/random.html .
Правила озеленения и нормативные значения из этого источника не извлекаются.
