# GreenCAD Desktop 0.4 — единый пакет данных и встроенные справочники

## Пользовательский путь

После открытия DXF или .gcp нажмите **«Справочники…»** рядом с кнопками проверки.
Окно не блокирует редактирование карты. Выбор строки не изменяет план или базу.

- **Растения**: поиск по названию/ID, исходные группы, диаметр кроны в расчётном
  состоянии (если действительно записан), требование дренажа, число записей.
  Нижняя таблица показывает известные и отсутствующие характеристики. Выбор
  характеристики раскрывает значение, исходную формулировку, ID записи, файл,
  лист/ячейку или JSON-путь и проверки-потребители. Числа для размеров не созданы.
- **Правила размещения**: все 13 подключённых определений и 69 неподключённых
  записей реестра. Видны включение в проект, реализация и эффективные параметры.
  Числа 3/1/5/3 по-прежнему TEST. Рядом с исходной нормативной записью отображается
  её область применимости и статус; она не включается автоматически.
- **Условия участка**: текущий сценарий A1, грунт, категория территории,
  диапазоны проектных типов, состав исходных геометрических объектов для проверок.
  Постоянное значение сценария не объявляется измерением, а число объектов —
  готовым расстоянием в каждой точке. Настройка — через «Выбрать проверки…».
- **Источники и версия**: SHA-256 пакета, хеши книг/JSON/профиля, исходные сведения
  об источниках и их ограничениях. Статус нормативов этой доработкой не обновлялся.

Поиск есть у каждой таблицы, заголовки сортируют строки; таблицы и подробности
прокручиваются. Нижняя панель закреплена. Диалог только для просмотра, редактор
произвольных исходных параметров в него не добавлен.

## Что стало общим

```
Две исходные JSON-копии реестров + именованные листы двух XLSX
                    + явный профиль реализованных операций
                                  ↓
              reference_build: проверка и сборка
                                  ↓
                   ReferenceBundle (один снимок)
                     ↙                      ↘
             окно справочников       CheckContext / PointEvaluator
                                              ↓
                                       отчёт и карта
```

`reference_data.py` не зависит от Tk или Shapely. Снимок возвращает копии записей,
не позволяет менять данные через таблицу. Он закрепляется в EditorSession.
Запрос проверки несёт ссылку на этот же read-only снимок; фоновый расчёт не
перечитывает справочники с диска в середине прохода.

`catalog.load_plants(reference)` и `load_object_types(reference)` теперь читают
пакет. Старые plants_index.json, plant_check_facts.json, site_types.json оставлены
как исторические совместимые файлы, но расчёт и новое окно их не используют.
`data/check_rules.json` остался входом СБОРЩИКА, а не независимо читаемой при
каждой проверке таблицей. Его изменение применяется только после пересборки.

### Конкретные связи

Для R.soil.drained сборщик связывает `plant.drained_soil_required` из записи
реестра с `site.soil_drained` и существующим булевым оператором. Примечание [4]
остаётся источником, а не условием вида «номер 4 найден — значит true» в коде.
Для Тсуги канадской PER.perspective.conifer_tree.004 значение V02205 соответствует
`GreenCAD_registry_v1.xlsx`, `03_Значения!E2210`. Для явно записанного отсутствия
требования (false) возвращается NOT_APPLICABLE; отсутствие записи — UNKNOWN.

Территориальная рекомендация читает `plant.territory_mark` с контекстом территории
из тех же строк значений. Исходные растительные группы не объединяются; знак минус
остаётся рекомендацией, не обязательным запретом.

В трёх тестовых проверках расстояния селектор типов объектов и основание измерения
берутся из связанного F.gas_axis/F.curb/F.wall словаря территории. Порог берётся из
тестового профиля или явно сохранённой настройки проекта. Поле расстояния не
порождает нормативный порог. Для домена/исключений остаётся объявленный проектный
селектор. Поля среды этой версии всё ещё постоянны по участку.

Исходные формулировки/`expression` в реестре не исполняются как код. Поддержан
ограниченный, явно проверяемый набор связей существующих операторов. Новая
формула требует регистрации и тестирования обработчика. Эта версия НЕ превращает
весь реестр в автоматически работающую нормативную экспертизу.

## Воспроизводимая сборка

В `data/reference_sources.zip` лежат неизменённые четыре исходных файла: обе
книги v1 и обе полные JSON-копии. Это не изображения планов и не полные издания
нормативных актов. `data/reference_bundle.json.gz` — заранее собранный пакет;
первый запуск не требует Excel, серверов, сети или дополнительных библиотек.

```
python tools/build_reference.py --check
python tools/build_reference.py --output data/reference_bundle.json.gz
```

Первое действие пересобирает в памяти и сравнивает результат, ничего не записывая.
Сборка детерминирована: одни входы дают одинаковые канонические байты и SHA-256.
Для текстового профиля check_rules.json хешируется канонический JSON: перевод
строк LF/CRLF при получении через Git на Windows не меняет пакет. Для исходных
книг/JSON в source-комплекте сохраняются хеши фактических байтов файлов.

Чтобы использовать изменённую копию книги:

```
python tools/build_reference.py --registry-xlsx path/to/GreenCAD_registry_v1.xlsx --site-xlsx path/to/GreenCAD_site_dictionary_v1.xlsx --output my_reference.json.gz
```

В окне доступна кнопка **«Собрать из Excel…»**: последовательно выбираются две
книги, затем строится проверенный пакет и запрашивается подтверждение его применения.
Сбой сборки или отмена не меняют текущий проект. При перестроении используются
профиль реализованных проверок поставки и полные исходные JSON как база для
дополнительных исходных столбцов/таблиц. Это не слияние со случайными файлами.

### Граница XLSX-адаптера

Поддерживается конкретная схема книг **v1** (заголовки в строке 5, стабильные ID).
Авторитетно считываются:

- Реестр растений: 02_Растения (идентификация), 03_Значения (включая контекст,
  значение, статус и источник), 04_Параметры, 05_Поля, 06_Проверки, 08_Примечания.
- Словарь территории: 02_Объекты (имена/роль/пояснения), 04_Параметры (описания),
  06_Поля (типы объектов, роль, параметры, способ получения).

У остальных листов и невынесенных колонок источник — соответствующая полная
JSON-копия в комплекте. В частности, изменения чисел в листе 07_Отступы сами по
себе НЕ включают нормативный профиль и не меняют TEST-пороги. Геометрические
варианты/профили дополнительных свойств не угадываются из текста листов.
Новые объекты и растения, требующие полного паспорта, добавляются через полную
JSON-структуру (а не неполную строку XLSX). Это явное ограничение адаптера.

Формулы в машинно читаемых входных столбцах отклоняются: их кэш не принимается за
актуальное число. Формулы служебных итогов не участвуют в сборке. Числовые,
логические, списковые и неизвестные значения различаются. Повторы ID, неоднозначные
факты, неверные ссылки, типы и неподдерживаемые связи блокируют сборку.

Можно строить непосредственно из JSON:

```
python tools/build_reference.py --registry registry.json --site site.json --json-only --output my_reference.json.gz
```

Для изменённых JSON нет притворной ссылки на старую Excel-ячейку: происхождение
соответствует реально выбранному входу. Если одновременно явно указана XLSX,
её поддерживаемые таблицы имеют приоритет над исходной JSON-базой.

## Сохранение и обновление

**.gcp v3** содержит `source.dxf`, `project.json`, `reference.json`. Снимок пакета
и настройки сохраняются вместе; контрольная сумма проверяется при открытии.
Файл можно перенести на другую установку, не подменяя его справочник данными этой
установки. Отчёт и карта — производные результаты, после открытия пересчитываются.

Проекты схем 1 и 2 читаются с текущим пакетом поставки. В «Источники и версия»
показано, что у старой сессии собственного справочника не было; точную прежнюю
конфигурацию, не сохранённую в файле, восстановить невозможно. Старые редакторы
не умеют открывать v3 — перед обновлением оставьте копию прежних .gcp.

«Обновить пакет…» принимает только подготовленный .json/.json.gz. Перед применением
проверяется структура. Если из нового пакета пропала используемая запись растения,
обновление отклоняется. Обновление отменяется через Undo; прежний снимок остаётся
в истории сеанса. Настройки/лимиты пользователя не перезаписываются базовыми
значениями обновлённого справочника. Ctrl+S сохраняет принятый снимок на диск.

Смена пакета изменяет fingerprint проверки/карты. Исчезает прежняя зелёная обводка,
карта скрывается как устаревшая. Отмена до прежнего снимка восстанавливает прежний
fingerprint. Просмотр, сортировка и поиск ничего не обесценивают.

**DXF-обмен не изменён.** DXF сохраняет геометрию/метаданные посадок прежним способом,
но сам полный пакет справочников в DXF не встраивается; для воспроизводимого сеанса
нужен .gcp. Отчёт .checks.json указывает bundle ID, источники и происхождение
использованных значений. Правила и карта работают с одним PointEvaluator.

## Ограничения

Это техническая связка и просмотр, не новое исследование нормативов. Не добавлены
неизвестные размеры/цены/сроки жизни, новые экологические формулы, авторасстановка,
редактирование справочника из таблицы. Статусы и оговорки исходных источников сохранены.
Хеш подтверждает согласованность снимка, но не юридическую или биологическую истинность.
Нативная Windows/AutoCAD/nanoCAD не проверялись; GUI проверен через Linux/Xvfb.

Технические источники: Python tkinter threading model и zipfile decompression pitfalls:
https://docs.python.org/3.13/library/tkinter.html#threading-model
https://docs.python.org/3.13/library/zipfile.html#decompression-pitfalls
