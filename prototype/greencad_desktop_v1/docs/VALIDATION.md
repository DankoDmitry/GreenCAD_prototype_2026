# Проверка существующего плана (обновлено для 0.4)

Кнопка **«Проверить допуски»** проверяет все текущие посадки по выбранным условиям.
Она не добавляет, не удаляет и не перемещает посадки. Нет автоматической расстановки.
Все вычисления работают локально; сетевые сервисы не требуются.

## Обновление и первый запуск

Закройте окно редактора. Перед обновлением сохраните свои проекты и зафиксируйте собственные
изменения кода в GitHub Desktop либо сделайте резервную копию папки.

При обновлении из `GreenCAD_Desktop_v0.2_update.zip` скопируйте содержимое архива непосредственно
в корень существующего редактора (где лежит `run_editor.py`), с заменой перечисленных файлов.
В этом архиве нет `.git`, `.venv` и пользовательских `.gcp`: они не заменяются.
Если вы меняли те же исходники, сначала сравните и объедините изменения, не перезаписывайте их вслепую.
Подробная инструкция: `docs/UPGRADE_0_2.md`.

Повторно запустите `setup_windows.bat`: добавлена библиотека `shapely==2.1.2`.
Затем `START_WINDOWS.bat`. Свою `.venv` удалять не нужно.
Когда изменения уже опубликованы в вашем репозитории, на другой машине вместо копирования
архива достаточно обычного Fetch/Pull. Эта поставка сама по себе не меняет GitHub.

Для первой проверки откройте «Демо», создайте T1 в точках (20,10), (40,31), (40,33),
(-3,10), задавая точные координаты в панели свойств. Нажмите «Применить свойства»
после ручного ввода. Нажмите «Проверить допуски».
При начальном наборе результат: PASS, FAIL, PASS, FAIL соответственно.
В (40,31) до оси газа один метр, а начальный **тестовый**, не нормативный минимум — 3 м.
В (-3,10) нарушены два условия: центр вне зелёной зоны и внутри дороги.

## Список и смысл проверок

Реализованы **13** определений правил и **7** общих обработчиков:

| Условие | Основание и ограничения |
|---|---|
| Внутри зелёной зоны | Проектное условие R.domain; только центр, граница включена |
| Вне запрещённых площадей | Явные исключения, дороги, проезды, тротуары, дорожки, здания; выбранная проектная модель |
| От оси газопровода | Проектный TEST-порог 3 м, редактируется; НЕ нормативный отступ |
| От края бордюра | Проектный TEST-порог 1 м, редактируется |
| От наружного контура здания | Проектный TEST-порог 5 м, редактируется |
| Между новыми посадками | Общий TEST-порог 3 м между центрами, редактируется |
| Рекомендация для территории | Исходная отметка из перечня растений: + / − / неизвестно; минус не становится запретом |
| Дренированность | Прямое условие примечания [4] исходного ассортимента |
| Рыхлость | То же |
| Отсутствие засоления | То же |
| Отсутствие уплотнения | То же |
| Отсутствие застойного увлажнения | То же |
| Влажность A1 | Сценарный параметр 0–1 и отдельно задаваемый диапазон проектного типа |

Начальный набор: зелёная зона, запрещённые площади, тестовый отступ от газа.
**Это не комплексная нормативная проверка.** Числа 3 / 1 / 5 / 3 не получены из СП
и не выдаются за действующий правовой профиль. Корнезащита их не уменьшает.

В диалоге **«Выбрать проверки…»**:
- галочки включают/выключают правила;
- вкладка «Параметры» задаёт отступы, A1, условия грунта, категорию территории;
- A1 и условия грунта в этой реализации постоянны по всему участку и заданы пользователем;
- диапазон A1 задаётся отдельно для проектного типа, не приписывается виду растения;
- «Отсутствующие объекты» позволяет явно подтвердить отсутствие категории;
- «Не подключено» показывает 69 оставшихся записей исходного реестра без заявления об их исполнении.

Пустой слой сам по себе не подтверждает отсутствие сетей. Категория, объявленная
отсутствующей, но содержащая объект, даёт UNKNOWN. Неизвестная классификация
нетекстовых сущностей и неразрешённые XREF блокируют подтверждение геометрических проверок.
Скрытие слоя в интерфейсе не выключает проверки.

## Результаты и отчёт

PASS — выбранные проверки выполнены. FAIL — найдены нарушения. UNKNOWN — не хватает
данных или поддерживаемой расчётной геометрии. ERROR — внутренняя ошибка обработчика.
WARNING — рекомендация, а не обязательный запрет. Неприменимые условия имеют отдельный
статус; пустой список правил никогда не даёт PASS. При отсутствии посадок результат EMPTY.
Если выбраны только рекомендации, обязательные условия считаются NOT_CHECKED.

Проверки продолжаются после первого нарушения: отчёт содержит все результаты по каждой
посадке, actual/required, единицы, ID объектов, источник условия и связанные параметры.
Результаты грунта для растений без явно извлечённого примечания [4] — UNKNOWN, а не
ложное предположение о наличии или отсутствии устойчивости.

Перенос, изменение растения, проектного типа, режима, классификации или настроек
делают отчёт устаревшим. Изменение масштаба/видимости слоёв — нет. При возврате к
точно тому же снимку через Undo отчёт снова соответствует данным. Во время drag
старая зелёная обводка не переносится в новое, ещё не проверенное положение.

Рабочий `.gcp` сохраняет настройки; их правки участвуют в Undo текущего сеанса. **Сам отчёт является
производным результатом**. После открытия `.gcp` проверку нужно запустить заново.
Формат проекта — версия 3 со снимком справочников; версии 1 и 2 читаются с текущим пакетом. См. REFERENCE_DATA.md.
Старый редактор отвергает версию 2, а не молча теряет настройки.
История Undo живёт в текущем сеансе; файл сохраняет текущее состояние настроек, не весь стек Undo.

Экспорт DXF сохраняет исходную основу и ручные посадки прежним механизмом.
Рядом записывается `.checks.json`: CURRENT, STALE либо NOT_CHECKED, снимок отчёта
и SHA-256 выходного DXF. Выгрузка черновика разрешена, но не маскирует отсутствие проверки.
Кнопка «Отчёт» также позволяет сохранить отдельный JSON. Экспорт не запускает расчёт
самостоятельно: свежая проверка — отдельное осознанное действие.

## Реестр и исполняемый код

С версии 0.4 вычислитель и UI используют закреплённый `ReferenceBundle`.
Почвенные условия читают типизированные записи значений, не номера примечаний.
`check_rules.json` — вход сборщика, не живой источник внутри прохода. Подробно — `REFERENCE_DATA.md`.

Исторические файлы и роли:

- `data/check_rules.json` — определения правил, ссылки на R.domain/R.territory/R.soil.*,
  F.gas_axis/F.curb/F.wall, источники, обработчики и TEST-параметры.
- `data/plant_check_facts.json` — историческая выборка (расчёт 0.4 её не читает) для всех 329 ID из
  `GreenCAD_registry_v1.json`; источник зафиксирован SHA-256. Идентификаторы совпадают с
  имеющимся `plants_index.json`, строки сортов не объединялись.
- `docs/REGISTRY_NOT_IMPLEMENTED.json` — оставшиеся 69 исходных проверок. Это не
  активированный нормативный профиль, и новой правовой сверки документов здесь не было.
- `checks.RuleOperator` — общий интерфейс исполнителя. Новую неизвестную операцию
  нельзя включить одним именем и получить успех: отсутствие обработчика даст UNKNOWN.
- `checks.make_request(session)` — независимый снимок без Tk, пикселей и Undo.
- `checks.validate_plan(request)` — отчёт без изменения плана и файлов.
- `check_geometry.py` — отдельное чтение исходной DXF-геометрии в метрах.
- `checks_ui.py` — выбор правил, параметры, отчёт и связь с редактором.

## Расчётная геометрия и точность

Поддерживаются прямые LINE, LWPOLYLINE и POLYLINE без bulge/сглаживания;
AREA/OUTER_CONTOUR требуют замкнутых корректных контуров. HATCH поддерживается
с простыми прямолинейными полилинейными кольцами и hatch_style=0; отверстия и острова
сохраняются. POINT и CIRCLE с явной ролью CENTER задают центр, не размер знака.
Ось, край и наружный контур не подменяются друг другом.

Кривые, дуговые границы, INSERT, MPOLYGON и остальные неподдерживаемые значимые
конструкции дают UNKNOWN для связанных проверок. Широкая полилиния может задавать
ось, но её ширина не принимается за явно переданный внешний контур.
Это более узкий набор, чем набор отображаемых объектов: красивый вид не означает
наличия проверенной расчётной геометрии. Допуски считают по исходным координатам,
а не по упрощённым экранным вершинам. Модель плоская: высота/глубина не снимают запретов.

Сравнения расстояний: `actual >= required`, без скрытого расширяющего эпсилона.
Используется численная геометрия GEOS с double; это не интервальная сертификация.
Пространственный индекс STRtree ускоряет выбор соседей, отчёт при равных расстояниях
имеет устойчивое упорядочение по ID. Память/скорость на предельных CAD-файлах не проверялись.

## Проверка без окна

```powershell
.\.venv\Scripts\python.exe tools\check_plan.py examples\demo_session.gcp --output checks.json
```

Можно передать `--settings settings.json`. Код выхода: 0 — PASS/WARNING;
2 — есть нарушения; 3 — пусто/не проверено/недостаточно данных/ошибка обработчика;
4 — ошибка чтения или подготовки. Используется тот же исполнитель, что в окне.

Тесты: `RUN_TESTS_WINDOWS.bat` либо `python -m unittest discover -s tests -v`.
В Linux без физического дисплея: `xvfb-run -a python -m unittest discover -s tests -v`.

Технические первоисточники библиотек:
- https://shapely.readthedocs.io/en/2.1.2/strtree.html
- https://ezdxf.readthedocs.io/en/stable/dxfentities/hatch.html
- https://docs.python.org/3.13/library/tkinter.html#threading-model
